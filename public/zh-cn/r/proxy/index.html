常见问题

为什么不同网站看到的 IP 不一样？

因为你的代理在按规则分流。Clash、Surge、Shadowrocket、sing-box 这类带规则的代理和 VPN，会按要去的网站挑线路：国内网站直连，AI 服务走一个节点，其他网站走另一个。所以只查一个网站，只能看到其中一条线路。这个页面同时问几十个地方，再按网络把结果归成几个出口。

怎么知道 ChatGPT、Claude 看到的是哪个 IP？

靠 Cloudflare 自带的一个公开地址。ChatGPT、Claude 这些网站都在 Cloudflare 后面，自己的域名下有 /cdn-cgi/trace，会告诉你「连过来的是哪个 IP」，任何网页都能读。你的浏览器像平时一样连 chatgpt.com，走的就是你的规则给它分的线路，读回来的就是 chatgpt.com 看到的 IP。

什么是 WebRTC 泄露？

就是代理没管住的一条路，你的真实 IP 可能从这里漏出去。WebRTC 是浏览器里做视频通话的功能，它会通过 UDP 去问 STUN 服务器「我的公网 IP 是多少」。很多代理只转发 TCP，这个 UDP 请求就从你自己的线路直接出去了；而且任何网页都能读到结果，不会弹出提示。如果 STUN 服务器看到的是本地 IP，网站看到的却是代理，页面就会报泄露。要堵上它，可以在代理里打开 UDP 转发或 TUN 模式，或者用浏览器扩展限制 WebRTC。

什么是 IPv6 泄露？

代理只管 IPv4，而你的线路又有 IPv6 时，走 IPv6 的连接可能绕过代理直接出去。「仅 IPv6」那组检测点会显示 IPv6 流量实际从哪个出口出去。如果报了泄露，可以让代理也接管 IPv6，或者在系统或路由器里关掉 IPv6。

怎么分辨本地出口和代理出口？

看 IP 归谁。注册在云服务商或机房名下（Amazon、Google Cloud、阿里云、DigitalOcean 等）的 IP 标为代理；第一个属于宽带运营商的 IP 当作你的本地线路。所以住宅代理，或者架在运营商网络上的 VPN，用这个办法分不出来。

「本站东京服务器」那组测的是什么？

那是 1ms.dog 自己在东京的一台服务器。别的检测点换的是目的地，这组换的是端口和协议：同一个地址，用 TCP 连 443、4433、8080、8443、9443、10443，再用 UDP（STUN）问 3478、19302、51820、40000。目的地没变，出口却不一样，就说明你的代理按端口或协议分流，比如只接管了 TCP。443 那一项还会读出 MSS（每个 TCP 包最多装多少数据）：明显小于常见的 1460 时，这条线路可能套了一层隧道，比如 VPN。运营商的隧道和一部分手机网络也会这样，所以这只是提示。

检测结果会发到这个网站吗？

不会。浏览器直接去问每个检测点，本站只提供静态网页，看不到你的结果。本站自己的检测点（「本站」那一项和「本站东京服务器」那组）会看到你连接用的 IP 和端口，只原样回给你，不记录。另外有两种情况由你自己决定：「分享」会把结果写进链接 # 后面的部分，打开链接时这部分不会发给服务器；「报告问题」会附上这次检测的概况，不含 IP 地址。截图前可以先点「隐藏 IP」。
