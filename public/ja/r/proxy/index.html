よくある質問

サイトによって見える IP が違うのはなぜですか？

プロキシがルールに従って通信を振り分けているからです。Clash、Surge、Shadowrocket、sing-box などのルール付きプロキシや VPN は、行き先ごとに経路を選びます。たとえば中国のサイトは直接、AI サービスはあるサーバー、それ以外は別のサーバー、という具合です。そのため 1 つのサイトで調べても、見えるのはそのうち 1 本の経路だけです。このページは数十か所に同時に問い合わせ、結果をネットワークごとにまとめます。

ChatGPT や Claude に見えている IP がなぜ分かるのですか？

Cloudflare が用意している公開の仕組みを使っています。ChatGPT や Claude などのサイトは Cloudflare の配下にあり、自分のドメインの /cdn-cgi/trace で「接続してきた IP」を返します。これはどのページからも読み取れます。ブラウザはいつもどおり、ルールが選んだ経路で chatgpt.com に接続するので、読み取った IP がそのまま chatgpt.com から見えている IP です。

WebRTC 漏れとは何ですか？

プロキシが押さえきれていない抜け道で、本当の IP がここから漏れることがあります。WebRTC はブラウザのビデオ通話に使われる機能で、UDP で STUN サーバーに「自分のグローバル IP」を問い合わせます。プロキシの多くは TCP しか転送しないため、この UDP 通信は自分の回線から直接出てしまいます。しかもその結果は、どのページからも許可なしに読み取れます。STUN サーバーにはローカルの IP、サイトにはプロキシが見えている場合、このページは漏れとして表示します。防ぐには、プロキシアプリで UDP 転送や TUN モードをオンにするか、ブラウザの拡張機能で WebRTC を制限してください。

IPv6 漏れとは何ですか？

プロキシが IPv4 しか扱わず、回線に IPv6 もある場合、IPv6 の通信がプロキシを通らずに出ていくことがあります。IPv6 専用のチェック先を見ると、IPv6 の通信が実際にどの出口から出ているかが分かります。漏れていたら、プロキシで IPv6 も扱うよう設定するか、端末やルーターで IPv6 をオフにしてください。

ローカルとプロキシはどう見分けているのですか？

IP の持ち主で判断しています。クラウドやホスティング事業者（Amazon、Google Cloud、Alibaba、DigitalOcean など）に登録された IP はプロキシ、最初に見つかったプロバイダーの IP をあなたの回線とみなします。そのため、住宅用プロキシやプロバイダー網上の VPN は、この方法では区別できません。

「1ms.dog の東京サーバー」のグループは何を調べているのですか？

1ms.dog が東京に置いている自前のサーバーです。ほかのチェック先は行き先を変えますが、このグループは行き先を固定し、ポートとプロトコルだけを変えます。同じアドレスに TCP の 443、4433、8080、8443、9443、10443 で接続し、UDP（STUN）の 3478、19302、51820、40000 に問い合わせます。行き先が同じなのに出口が違えば、プロキシがポートやプロトコルで振り分けています（TCP しか扱わない、など）。443 では MSS（TCP の 1 パケットに載るデータの上限）も読み取ります。一般的な 1460 よりかなり小さければ、VPN などのトンネルを通っている可能性があります。プロバイダーのトンネルや一部のモバイル回線でも小さくなるため、あくまで目安です。

結果はこのサイトに送られますか？

送られません。ブラウザが各チェック先に直接問い合わせ、このサイトは静的なファイルを配信するだけなので、結果は届きません。このサイト自身のチェック先（「このサイト」と「1ms.dog の東京サーバー」のグループ）には接続元の IP とポートが見えますが、そのまま返すだけで記録しません。ほかに、あなたが自分で選ぶものが 2 つあります。「共有」はリンクの # より後ろに結果を書き込みます。この部分はリンクを開いてもサーバーに送られません。「問題を報告」は今回のチェックの概要を添付しますが、IP アドレスは含みません。スクリーンショットの前には「IP を隠す」を押してください。
